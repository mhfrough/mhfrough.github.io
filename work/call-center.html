Case studyFeb to Mar 2023, Angular frontend

A call center for restaurants.Phone orders, typed once.

Customers phone one number and order from several restaurants. I built the Angular portal behind it: the agent types the caller’s number and a returning caller fills in, picks items priced by size, and the restaurant finds the order in its own list, moves it through five statuses and prints the receipt.

The stack

Angular 15 with Bootstrap components, Firebase for one job, push notifications, and two libraries for the receipt.

  • Web

    Lazy-loaded modules, a sign-in guard, an interceptor for the token and one facade over the data services.

Decisions and what I’d change

A small portal, built and fixed in a few weeks, for people who use it with a phone at their ear.

  1. 01

    The phone number comes first

    An agent hears the number before anything else. After five digits the form searches past orders and fills in the name, address and restaurant, so a regular caller is ready before they finish saying hello.

  2. 02

    One screen, a set of calls per role

    The call center and the restaurants read and update orders through different endpoints. A small map keyed by role picks the right one, so the order list, the details and the status change are one component each, not two.

  3. 03

    Prices live on the size

    A pizza at 26 cm and at 32 cm are one product with two prices. Picking a product loads its sizes, and picking a size sets the line price, so an agent never types a price for something on the menu.

  4. 04

    Push to the kitchen

    A restaurant does not watch a list all evening. The portal asks each browser for push permission and a Firebase token, a service worker shows pushes while the tab is in the background, and a bell in the header keeps the unread ones.

  5. 05

    A text PDF, not a photo of one

    The receipt was HTML drawn to a canvas and saved as an image inside a PDF: heavy, soft when zoomed, unsearchable. Today I’d write the PDF as text, as the demo above does, or ship a print stylesheet.

  6. 06

    Guard the routes, not just the menu

    A directive hides menu items by role and the API checks the token, but the routes only check that someone is signed in. Today I’d add a guard per role and debounce the phone lookup so it searches once per pause, not on every key.
