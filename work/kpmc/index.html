Decisions and what I’d change

A public body, a hard deadline and three kinds of staff in one back office.

  1. 01

    One directive for roles

    Agents, supervisors and admins share one back office. A single structural directive shows or hides each menu item, column and button by role, so a new screen gets its rules in one line.

  2. 02

    Fifteen screens, one base

    News, tenders, schemes, accounts and the rest are the same list, search and form. A generic base component and one facade over the services kept each new module small and the same as the last.

  3. 03

    Prerender everything

    A government site is read on slow phones and found through search, so every route is prerendered. The price is guarding every touch of the browser so the server build never breaks.

  4. 04

    A map link, not a map

    Complaints carry a GPS point. Opening it in Google Maps gave staff directions on their phones without a map library in the bundle.

  5. 05

    Hiding is not enforcing

    The directive hides what a role should not see; the API has to refuse it too. Today I’d add route guards per role on top, so a typed address can’t open a screen a role should never reach.

  6. 06

    Charts next to the PDFs

    Reports are tables and server-drawn PDFs. A ward map and a trend line of open complaints would show a supervisor in seconds what a table takes minutes to say.

A public service that needs a back office?

Role-based back offices, prerendered public sites and the reports people actually use.
