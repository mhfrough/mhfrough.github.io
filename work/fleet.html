The staff admin

Where the office runs the fleet: vehicles, drivers, hires, compliance, tasks and support chat. Angular 21, standalone and signal based, every page lazy loaded, light and dark themes tuned for contrast.

The real admin, built and run on my machine against invented data: every name, plate, depot and figure is made up, and the client’s name and logo are removed.

Four apps, one API, one database

Every client talks to the same NestJS API. Every row carries its company, and the API refuses a query that does not know whose data it is reading.

What I built

The team shared the product. These parts are mine, end to end or close to it.

  • The staff admin

    The largest share of its commits: drivers, the hire calendar, vehicles, the compliance dashboard, reports, tasks and settings.

  • The driver app API

    Nine phases: SMS sign-in and the home card, documents, payments, fines, holidays, incidents, the walkaround, tests and returns.

  • Passkeys for staff

    WebAuthn sign-in with discoverable credentials, so there is no username to type, and per user control over every passkey.

  • Payments and receipts

    Saved cards, bank transfers with scanned receipts, payment links by SMS, and one reconciliation path that cannot record twice.

  • Hire documents

    The hire agreement, the condition report with its damage diagram and photos, the return report and permission letters, as PDFs.

  • Live chat and alerts

    Socket.IO notifications and support chat with typing, presence, read receipts and voice notes, split into its own widget app.

A daily check the server can trust

Before the driver app unlocks each morning, the driver walks round the car in five steps: bodywork, tyres, lights, safety kit and mileage. The API rechecks every rule itself, whatever the app sends.

API response

Change a tread depth, flag a tyre or take the spare out, then submit. The server checks the same rules whatever the app sends.

Sample check, nothing is sent

  1. 01

    Legal minimum

    A tyre under 1.6 mm cannot be passed. The API rejects it unless it is flagged.

  2. 02

    One defect per flag

    Every flagged item needs exactly one defect with a photo and a severity.

  3. 03

    Worst one wins

    Minor, report or not safe. The check takes the worst severity it was given.

  4. 04

    Grounded, one way

    Not safe takes the car off the road and alerts staff. Only a person puts it back.

Nothing expires quietly

MOTs, insurance, council tests, driving licences and taxi badges all expire. An hourly scan across every company raises each alert once, and only for drivers and cars that are actually on the road.

  • Driver alerts only on an active hire
  • Vehicle documents only if a council requires them
  • A renewal receipt adds 30 days to a badge
  • Date-only fields are days, not instants

Decisions and what I’d change

A hire business runs on dates, money and safety. Most choices came down to not trusting a clock, a client or a retry.

  1. 01

    One card, not a feed

    The driver home screen shows exactly one card, chosen by fixed priority: a grounded car outranks a fine, a fine outranks an expiring licence. Everything else waits in notifications.

  2. 02

    Record now, let the webhook catch up

    An in-app card payment is recorded straight away, so the driver sees it done. The webhook finds it paid and stops. Next I would back that status check with a unique constraint, so two webhooks at once cannot both write.

  3. 03

    Fail closed on tenancy

    The company lives in request context, and a scoped query with no company throws instead of returning everything. A test scans the code for queries that skip it. I moved the driver app’s services onto it.

  4. 04

    Passkeys without server state

    The WebAuthn challenge is signed into a token that lives two minutes, so any API instance can check it. No session table, no sticky routing.

  5. 05

    Dates are days

    An expiry shown a day early in one view and on time in another came from parsing date-only fields as UTC. I fixed it with one shared date-only parser and applied it across reports, tests, driver pages, holidays and bookings.

  6. 06

    Photos sized at the source

    Full-size photos sent as base64 timed out on weak signal. My fix resizes them to 1600 px before upload and gives slow uploads longer. Next would be uploading straight to storage instead of through the API.
