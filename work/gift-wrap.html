The storefront

Built to feel like a phone app: a floating tab bar with a centred Build button, a sliding search and sticky totals. On a laptop the header turns into a floating glass bar.

The original build, rendered locally with its own sample catalogue. Product photos are stock images from Unsplash and Pexels.

The build studio

Five numbered steps on the left, a live summary on the right. The preview takes the wrap colour and the ribbon, and every line of the price is spelled out before the basket goes to the cart.

The problem and the approach

Online gift shops sell hampers someone else filled. The thesis asked what happens when the buyer fills it.

  • Mobile first

    Gifts are bought on phones, often last minute. A bottom tab bar, a raised Build action and sticky totals keep the next step under the thumb.

  • Price as you go

    Base, wrap and treats each add a line; the total is a computed signal, so it can never disagree with the summary beside it.

  • A basket is one cart line

    The finished basket is saved as a snapshot: base, wrap, ribbon, note and every treat. The cart shows exactly what was built.

  • Front first

    A thesis is judged on a demo. The catalogue lives in one service with the shape a real API would return, so the backend could slot in later.

What I’d do differently today

A tidy demo for a thesis. Here is what a real shop would need first.

  1. 01

    Agree the API before the polish

    The sample data has the right shape, but nothing enforces it. Today I’d write the API contract first and mock it at the network layer, so the Next.js backend would only have to meet it.

  2. 02

    One chip, one set of tokens

    A page style outranks the shared chip style, so the selected filter turns white on white; you can see it in the shots. One chip component with its own states would have stopped that.

  3. 03

    Prerender the shop

    It is a client-only app: titles and product JSON-LD appear only after JavaScript runs. Prerendering the product and category pages would give search engines and slow phones real HTML.

  4. 04

    Own the photos

    Product photos come from stock CDNs without fixed sizes, so cards jump as they load. Sized WebP files served with the app would load faster and never shift.

  5. 05

    Money in cents

    Totals add decimal dollars. A shop should store integer cents and format at the edge, so a basket of ten items can never be a cent off.

  6. 06

    Tests for the maths

    The only spec is the default one. The studio total, the free shipping rule and the cart’s quantity rules are exactly the code a few unit tests should hold still.
