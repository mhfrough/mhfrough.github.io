Hit a file size

For forms that say “under 100 KB”. Pinch finds the highest quality that fits, and makes the picture smaller only when quality alone cannot get there. This runs the same search live; watch it narrow down.

  1. 01

    Try your quality

    One encode at the chosen quality. If it already fits, that is the answer and nothing else runs.

  2. 02

    Halve the range

    Between quality 30 and one below yours, at most seven tries (five for AVIF), keeping the highest that fits.

  3. 03

    Then shrink

    If quality 30 is still too big, the picture gets smaller in 0.85 x 0.85 steps, as many as the size gap suggests, and the search runs again.

  4. 04

    AVIF finishes slow

    AVIF searches with a fast encoder setting, then encodes once more at full effort at the quality it found.

Upscale, with AI on your device

Smooth and Sharp resample, Pixel keeps hard edges for pixel art, and AI (detail) runs Real-ESRGAN in the tab. Drag the divider over Pinch’s own output.

Smooth 4xLanczosAI 4xReal-ESRGAN

hills.jpg, 160 × 160 crop to 640 × 640 · AI on WebAssembly in 9.6 s

  • WebGPU first, then WebAssembly

    A WebGPU device has to be created, not just found; if it fails, the WebAssembly build runs instead. Threads would need COOP and COEP headers, which GitHub Pages cannot send, so it runs on one.

  • Tiles with real context

    The image is cut into equal tiles, at most 256 px on WebGPU and 192 on WebAssembly, each read with 12 to 16 px of its neighbours, so memory stays bounded and there are no seams.

  • 2x from the 4x model

    For 2x the 4x network runs and each padded tile is reduced with Lanczos-3 before cropping, so the filter sees real pixels at the edges.

  • Transparency kept

    Alpha is resized on its own and put back. Hidden pixels first take the colour of their visible neighbours, so no stray colour bleeds into edges.

Five presets

One click sets format, size and quality for where the picture is going. No other tool in the research for Pinch offered them.

  • < 1 MB

  • jpg q82

Engineering details

Small things that keep a heavy tool calm inside one browser tab.

  • 01

    A pool of workers

    Up to four Web Workers, one fewer than the CPU cores. Compiled WebAssembly modules are shared between them, and the worker starts from a Blob URL of its own source, so restarts work offline.

  • 02

    Warm when idle

    Ten seconds after load, when the page is idle, every codec is fetched and compiled in the background, the 3.4 MB AVIF encoder last, and only the small ones on Save-Data. After that Pinch works with Wi-Fi off.

  • 03

    The original is kept

    If a file would come out larger in its own format, Pinch hands back the original and says so, with metadata stripped losslessly unless that would lose the photo’s rotation. Re-encoded files never carry EXIF or GPS.

  • 04

    Auto picks a format

    A quick look at the pixels decides: 32 colours or fewer, or many flat neighbours, is a graphic and goes to PNG; anything else is a photo and goes to WebP, which keeps transparency.

  • 05

    HEIC only when needed

    libheif is LGPL, so it lives in its own 3 MB file, loaded only when an iPhone photo is opened and the browser cannot decode it, and replaceable with any compatible build.

  • 06

    Bounded memory

    Output is capped at 12,000 px on the long side and 40 megapixels, with a note saying so. AI output stops at 16.8 megapixels, checked before any work, and the message says what size to try instead.

Decisions

Each one follows from the promise in the title: the work happens on your device, and you can check it.

  1. 01

    Ship the encoders

    WebP, AVIF, JPG and PNG are written by MozJPEG, libwebp, libavif and OxiPNG compiled to WebAssembly, not by the browser, so the same settings give the same file in every browser.

  2. 02

    Make privacy checkable

    Saying “nothing is uploaded” is cheap. The page counts every network request made after the first image, and names the two that can happen: the AI model from this site, and the GitHub star count.

  3. 03

    Convert the model ourselves

    No third-party ONNX copy: the official Real-ESRGAN checkpoint is read with a restricted unpickler and written as ONNX with float16 weights, half the size, checked against the PyTorch network.

  4. 04

    No CDN, no framework

    Every font, codec and script is served from the repository. Plain HTML, CSS and JavaScript, with esbuild only to build the codec worker; the page itself has no build step.

Limits, stated plainly

From the README and the questions on the page, because a privacy tool should be precise about what it does.

Works

  • Current Chrome, Edge, Firefox and Safari, on computers and phones
  • Opens JPG, PNG, WebP, AVIF, GIF, BMP, ICO, SVG and iPhone HEIC
  • Offline once loaded: compressing, converting and resizing need no connection
  • Batch with one set of settings, per-file changes and one ZIP
  • Keyboard shortcuts for every common step, listed on ?

Does not, by design

  • Very large pictures, above about 40 megapixels, are not handled at full size, so the tab does not run out of memory
  • GIF opens its first frame only; SVG and HEIC open but are not saved back
  • AI detail is a good guess, not recovered data: not for faces in evidence, small text or number plates
  • AI without WebGPU is slow: a 1 MP input at 4x takes minutes on WebAssembly
  • The first AI run downloads the 2.4 MB model and its runtime, then both stay in the browser’s cache

The stack

Static files you can host anywhere. Codecs are built once by a script; the page has no build step.
