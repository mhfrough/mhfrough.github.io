Swoop.Screenshots that stay on your computer.

A full-page capture extension for Chrome and a Print Screen app for Windows, sharing one free editor: arrows, boxes, numbered steps, blur and crop. There is no Swoop server, so nothing is uploaded. Mark up the sample here; the real editor is a click away.

Two ways in, one editor

A page in Chrome, or anything on the screen. Both end in the same editor and the same two exits: copy or save.

  • Manifest V3

    Swoop for Chrome

    Alt+Shift+S

    Click the Swoop button and it scrolls the page one screen at a time, joins the parts into one tall image and opens it in a new tab. Alt+Shift+V takes only the part you can see.

    • Save as PNG, JPG, WebP or PDF; a long page becomes several A4 pages
    • The last 12 captures stay in the browser
    • Right-click the picture for Copy, Save, Save as PDF, Undo and Delete
  • Tauri 2

    Swoop for Windows

    Print Screen

    Swoop waits in the tray. Press Print Screen and the screen under the pointer freezes, so menus and tooltips stay put. Drag over a part, mark it up where it is, then Enter copies and Ctrl+S saves.

    • Saves full size to Pictures/Swoop, named with the date and time
    • Starts with the computer, with a switch in the tray menu
    • Updating is running the new installer; settings are kept

Scroll and stitch

Chrome can only photograph what is on screen, so Swoop scrolls and takes the page one screen at a time. Real pages fight back: fixed headers, lazy images, cookie bars. Turn each fix off and capture again.

  • When the page scrolls inside a box, the largest scrolling box is captured instead
  • Smooth scrolling and scroll bars are switched off for the capture, then everything is put back
  • Fade-ins are waited for, but only animations that will end within 8 seconds
  • A page taller than 32,767 px is scaled to fit Chrome’s canvas, and the editor says so
  • Infinite feeds stop at 60,000 CSS px

Why not one DevTools call

The DevTools protocol can capture beyond the screen in one call, but Chrome then shows a yellow "is debugging this browser" bar on every capture, the install screen warns about full access, and full-height (100vh) layouts come out wrong. Scrolling a screen at a time is slower and works on real pages.

One editor, three places

One plain JavaScript file with no dependencies and no build step runs in the extension, the desktop overlay and the landing page. A sync script copies it into both apps, and the tests fail if the copies drift.

  • 01

    Any height

    Tall captures are cut into 4096 px tiles, never one giant texture, and one window-sized canvas is redrawn with the current zoom and pan.

  • 02

    Full resolution out

    Saving redraws the picture and every shape on an off-screen canvas at full size. Strokes scale with the capture’s pixel ratio, so a 2x capture gets 2x lines.

  • 03

    PDF without a library

    A tall capture is cut into A4-sized slices, each a JPEG, and written into a minimal PDF by one function of about 30 lines.

  • 04

    Two layouts

    Full, with the toolbar on top and zoom and pan, for the extension and the demo. Overlay, where you drag a selection first and the toolbar floats beside it, for the desktop app.

A small desktop app

Tauri 2 uses the web view the system already has, so the desktop app runs the same editor and still ships as a 1.4 MB installer.

  • 01

    A frozen screen

    The monitor under the pointer is captured first with the xcap crate, then shown full screen. You select on a still picture, like Lightshot, so menus and tooltips stay where they were.

  • 02

    Ready before you press

    The overlay window is made once at start-up and kept hidden, so it appears at once. Pixels reach it as raw bytes over Tauri’s binary IPC: a 12-byte header, then RGBA, with no PNG encode between.

  • 03

    Print Screen is your choice

    A switch, on by default. On, Swoop turns off Windows’ "Use the Print screen key to open screen capture" setting and, if another app holds the key, uses a low-level keyboard hook that sees it first. Off, it puts Windows’ setting back.

  • 04

    One copy, any trigger

    Only one copy runs. Running swoop --capture again starts a capture in the copy that is running, which is also how Wayland users bind a shortcut, since apps there cannot listen for keys.

  • 05

    Clipboard from Rust

    Copy goes through the arboard crate, with Wayland support switched on. Save asks Rust to write the PNG into Pictures/Swoop with a unique, dated name.

  • 06

    Built for size

    The release profile optimises for size, with link-time optimisation, one codegen unit, abort on panic and stripped symbols. The installer is per user and needs no admin rights.

Decisions

Swoop was planned against two tools people already use: GoFullPage in Chrome and Lightshot on the desktop.

  1. 01

    The editor is free, everywhere

    GoFullPage keeps crop and markup in its paid tier. Swoop has no paid tier and no watermark, and the same editor runs in every place it appears.

  2. 02

    Nowhere to upload to

    Lightshot uploads to a public server and hands out short links, and old links could be guessed in order. Swoop has no server, no account and no links: copy or save only.

  3. 03

    Only the tab you click

    The extension asks for activeTab, not every site, so it can see a tab only after you click its button and the install screen shows no "read all your data" warning.

  4. 04

    Tauri, not Electron

    Electron would ship its own browser in every install. Tauri borrows the system web view, keeps the editor shared, and builds for Windows and Linux.

Private by design

Five permissions, each with one job. The extension and the app make no network requests at all.

The extension's permissions and what each one is for
PermissionWhy Swoop needs it
activeTabCapture the tab you clicked Swoop on, and only that tab.
scriptingScroll that tab during the capture and put it back the way it was.
contextMenusCapture the whole page or the visible part from the button’s right-click menu.
storageKeep your capture settings, such as whether to scroll the page first.
unlimitedStorageKeep your recent captures in the browser; a long page is a large image.

  • No account

    Nothing to sign up for.

  • No links

    Copy and save only.

  • No tracking

    No analytics in the extension, the app or the page.

  • Open source

    MIT licence, every line on GitHub.

Status, stated plainly

From the README’s download table and its "Not yet" list.

Ready

  • Swoop for Chrome, in Chrome and in Edge, as a zip to load unpacked
  • Swoop for Windows 10 and 11, 64-bit, installed per user without admin rights
  • PNG, JPG, WebP and PDF, or copy to the clipboard
  • Releases built by GitHub Actions on every version tag, with Playwright tests on every push

Coming soon, or not yet

  • Linux: coming soon, as .deb for Debian and Ubuntu, .rpm for Fedora, and an AppImage
  • Mac: coming soon; until then, Swoop for Chrome works on a Mac
  • The Chrome Web Store listing is on its way; the installer is not code-signed yet, so SmartScreen may warn once
  • Selecting across several monitors, a timer and window capture
  • Capturing one element or a selected area in the extension, and pages that scroll sideways
  • Firefox and the Edge Add-ons store
