The life of an extraction

One run at a time per console. The operator starts it, the page polls its status, and the run ends in a report either way.

  1. 1Configure
  2. 2Start
  3. 3Running
  4. 4Paused
  5. 5Complete
  • 01

    Polled at your rate

    The status endpoint is called every 1, 3 or 5 seconds. The operator picks the rate and the browser remembers it.

  • 02

    Counted per table

    Each table reports its total, extracted, failed and duplicate rows and its records per second, rolled up into the run.

  • 03

    Pause, resume, cancel

    A running job can be paused and picked up again where it stopped. Cancel always asks for confirmation first.

  • 04

    Reported after

    Every run lands in the reports tab with its failed records and an activity log, ready to search and export.

Watch the job, not a spinner

Live counters for every run, per table. Pause it, cancel it, retry the rows that failed, and download the result when it is done.

Decisions and what I’d change

Jobs that run for an hour, files with millions of rows, and staff who must never wonder whether a run finished.

  1. 01

    Poll, at a rate the operator picks

    A status endpoint and a timer: 1, 3 or 5 seconds, saved in the browser. It needs nothing beyond plain HTTP, and on a slow link the operator eases it off without a release.

  2. 02

    Count every row three ways

    Extracted, failed and duplicate, per table and for the run. A finished job is only trusted when the three add up to the total, so the screen shows all of them, not one percentage.

  3. 03

    Show 1,000 rows, file the rest

    A statement over 1,000 entries shows the first 1,000 with a notice, and the PDF or CSV carries every row. The browser stays fast on accounts with years of history.

  4. 04

    An idle timeout that waits for downloads

    Five minutes idle signs a user out, but the timer pauses while a request is running. A long statement no longer logs someone out halfway through the file.

  5. 05

    One workspace, not four copies

    Each store got its own repo, copied from the same shell, so a fix in one was carried to the others by hand. Today I’d keep one workspace with a shared library and three thin apps.

  6. 06

    Typed responses and signals

    The services return untyped responses and the pages hold state in fields. Today I’d type every endpoint and move job state to signals, so a renamed field breaks the build, not a run.

Big data jobs that people need to trust?

Consoles that count every row, statements that scale, and internal tools that stay calm under load.
