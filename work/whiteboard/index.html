One SVG, a few HTML layers, overlays on top

Everything that moves with the board lives in world units under one transform. Everything that has to stay crisp at any zoom, like handles and guide lines, is drawn in screen pixels.

// ViewportService: all coordinate math in one place
screenToWorld(p) {
  return { x: (p.x - v.x) / v.zoom, y: (p.y - v.y) / v.zoom };
}

// Wheel and pinch: the point under the cursor stays put
zoomAt(anchor, factor) {
  const next = clamp(v.zoom * factor, 0.1, 8);
  const ratio = next / v.zoom;
  return {
    x: anchor.x - (anchor.x - v.x) * ratio,
    y: anchor.y - (anchor.y - v.y) * ratio,
    zoom: next,
  };
}
  • Pointer moves are coalesced to one update per animation frame, then flushed on release, so the last position is never dropped.
  • Two pointers pinch-zoom around their midpoint; Space or the middle button pans; Ctrl and the wheel zoom around the cursor.
  • The live board is SVG; exports redraw the scene on a canvas, so neither depends on the other.

The parts worth reading

Small, specific decisions that keep a canvas app from feeling like a web page.

  • 01

    Hit testing

    The click is rotated back into the element’s own frame, then tested against its box with a pad of 6 screen pixels at any zoom, so thin lines stay clickable when zoomed out. The list is walked backwards, so the topmost element wins. Locked elements are skipped.

  • 02

    Smart guides

    A computed signal that only runs during a move. It compares the selection’s left, centre and right, top, middle and bottom with up to 300 other elements, merges lines on the same axis and position, and stops at six. Grid snap makes the alignment exact; the guides show it.

  • 03

    Undo and redo

    Whole-scene snapshots taken with structuredClone at the end of a gesture, never mid-drag. A JSON comparison skips commits that changed nothing, the stack stops at 100, and a remote edit clears the stack so undo can’t bring back a peer’s stale copy.

  • 04

    Export without libraries

    Raster formats redraw the scene on a canvas; SVG is built as a string. The PDF is written by hand: one page, the board as a JPEG, fitted to A4, A3 or Letter. PNG, SVG and JSON can take just the selection, and PNG and SVG can write each selected object as its own file.

  • 05

    Images that fit

    Pasted, dropped or picked images over 300 KB are capped at 1600px and re-encoded to WebP before they reach the scene, because the scene autosaves to localStorage and one phone photo would fill it. SVG and GIF stay as they are. Crop, mask and boolean ops keep the original for reset.

  • 06

    Text is real text

    Text boxes and sticky notes are editable HTML: bold, italic, links that form as you type, checklists. A small pill rewrites a box through a throttled Gemini endpoint (improve, shorten, fix), and one undo restores the original wording.

Live editing through one relay

The server forwards; the clients merge. Every op carries whole elements, and each element resolves on its own: the newer updatedAt wins.

type SceneOp =
  | { kind: 'snapshot'; elements: Element[] }
  | { kind: 'upsert'; elements: Element[] }
  | { kind: 'delete'; ids: string[] };

// Merge: unknown ids append,
// known ids win only if same or newer.
for (const r of op.elements) {
  const mine = byId.get(r.id);
  if (!mine) next.push(r);
  else if (r.updatedAt >= mine.updatedAt) swap(mine, r);
}

What the gateway enforces

  • Presence lives in memory: document, then socket, then user.
  • Only a socket that joined a room can send into it.
  • Room ids up to 128 characters, names and colours up to 64. Malformed envelopes are dropped, not relayed.
  • Messages up to 5 MB, because images travel as data URLs.

Saved twice: in the browser, then on the server

Local first, so the board works with no account. Signing in adds a server copy, and the newer side wins on load.

  1. In the browser

    always on
    • Autosave 600ms after the last change, into localStorage.
    • A full quota shows “Not saved” instead of failing quietly.
    • Up to 30 named versions; restoring one is a single undo step.

  2. On the server

    when signed in
    • Find or create the default board, then keep the newer of the two copies.
    • Save the scene 2.5s after the last change; overlapping saves collapse into one trailing save.
    • Saving a version also snapshots it on the server.

Three tables, TypeORM on PostgreSQL

  • whiteboard_documentsid, title, ownerId, scene as jsonb, isPublic, shareRole, deletedAt for soft delete, timestamps
  • whiteboard_versionsid, documentId (indexed), scene as jsonb, label, createdBy, createdAt
  • whiteboard_collaboratorsdocumentId and userId, unique together, role viewer or editor

Access resolves owner first, then collaborator, then the public link’s role. Restoring a version first saves the current scene as “Auto-save before restore”, so a restore can itself be undone.

Decisions and what I’d change

A week, one author, and a board that had to feel like a tool, not a page.

  1. 01

    Signals, not a store

    Each concern is a small service with its own signals, and the view reads computed ones: visible elements, guides, the minimap. No actions or reducers; change detection follows the data.

  2. 02

    SVG for the board, canvas for export

    SVG gives crisp strokes at any zoom, DOM events and CSS transforms for free. Exports need pixels, so a separate canvas renderer draws them and the live board never waits on it.

  3. 03

    HTML for text

    An editable HTML box brings selection, input methods, spellcheck and links that SVG text never will. The price is two layers to keep in step, solved by giving both the same transform.

  4. 04

    Last writer wins, per element

    Elements are small independent records, so two people editing different elements both keep their work, and same-element conflicts resolve to the newest. A CRDT would be the next step, not the first.

  5. 05

    Snapshots for undo

    Copying the whole scene is the simplest undo that is always right. It costs memory once large images are on the board; inverse patches per operation are the fix.

  6. 06

    Local first

    The board saves in the browser before anything else, so it works signed out and offline. The server copy is an upgrade, never a requirement.

Where it stands

Checked against the code and a local run of the original build, with two browsers and a relay using the gateway’s event shapes.

Works

  • All twenty tools, with move, resize, rotate, group, align, distribute and layers.
  • Undo and redo, local autosave and named versions.
  • Every export and import, plus image crop, mask and boolean ops.
  • Live scene sync: a shape drawn in one browser appears in the other.

Not yet

  • Presence labels. The gateway sends cursors without a name or colour and wraps a joining user in an envelope the client reads as flat, so remote cursors arrive unlabelled and a peer joining after you breaks your avatar list.
  • Live rooms use an id minted in the address bar, not the saved document, and the socket is not authenticated: anyone with the link can join.
  • Cloud sync covers one default board for a signed-in account. Versions restore locally only; the server stores them, but no screen lists them.
  • Sharing, collaborators, public links and duplicate exist in the API with no screen yet.
  • Hit testing uses boxes, so a click just outside an ellipse but inside its box still selects it.
  • Offline today: it lived inside my previous site, which is archived.

Next

In the order I’d do them.

  1. 01

    Rooms on the document

    Join by the stored document id, authenticate the socket with the same JWT cookie as REST, and check the role before relaying an op.

  2. 02

    One presence payload

    The same shape for join and cursor events, with name and colour taken from the server’s presence map.

  3. 03

    Versions on the server

    A version list fed by the API, with restore going through the server so every client sees it.

  4. 04

    Inverse patches for undo

    Store what each operation changed, not the whole scene, so large images stop multiplying in memory.

  5. 05

    Exact hit testing

    Distance to the path for lines and arrows, the ellipse equation for ellipses, point in polygon for the rest.

  6. 06

    Images as files

    Upload each image once and reference it by URL, so scenes, ops and snapshots stay small.
