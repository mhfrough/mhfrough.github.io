Static where it can be, PHP where it must

The host is shared hosting with Apache and MySQL, no Node. So pages are rendered at build time, and the only code that runs on a request is PHP: the blog, the popup, the forms and the back office.

The rest of the back office

The parts nobody sees on the public site, and the ones that keep it honest.

  • Comment moderation

    Every comment waits for a person. Links, rude words and a pile of @ mentions raise a flag; nothing is rejected automatically. A hidden field catches bots.

  • Inquiries

    Contact messages land in a list with a status. A reply goes out by email from the site’s own domain and is kept with the message.

  • Activity and soft delete

    Every change writes who, what and when to an activity log. Delete hides a row instead of removing it, and lists show who changed it last.

  • Sign-in

    Repeated failed attempts lock an address out for a while. Passwords reset by an emailed link, and an idle screen covers the admin after 15 minutes.

One build, one folder

A single command produces everything the host needs. The result is dragged into public_html as it is: no server process, no deploy tool, nothing to keep alive.

  • 01

    One address per page

    /about is served from about.html. /about.html and /about/ answer with a 301 to /about, and the bare domain goes to www.

  • 02

    Pages from the database

    A blog post or policy page gets its title, description, share tags and text in the HTML from PHP, so link previews work without JavaScript.

  • 03

    Caching that survives a deploy

    HTML is always revalidated; hashed scripts and styles are cached for a year. An old page can never point at bundles that are gone.

  • 04

    A demo nobody indexes

    A second build for a /demo folder adds noindex to every page and header, turns crawlers away and drops the sitemap, and fails if any step did not take.

Decisions and what I’d change

A marketing site on shared hosting that also had to become a small CMS.

  1. 01

    No server to keep alive

    The host runs Apache and PHP, not Node. Prerendering at build time and flattening each route to one HTML file gave server-rendered pages with nothing running between requests.

  2. 02

    Schedules without cron

    Scheduled posts and campaigns are promoted at the top of every read, so they go live with the next visitor. A cron job is optional and only makes the timing exact.

  3. 03

    Delete means hide

    Every admin table soft-deletes, and the activity log keeps a copy of each person’s name. Removing a user never breaks history, and a mistake can be undone in the database.

  4. 04

    Hide in the screen, refuse in PHP

    One permissions service hides buttons a role cannot use. The real gate is a single check in each endpoint that answers 403, so a crafted request gets nowhere.

  5. 05

    Gate every endpoint

    The permission check guards the endpoints that change data. Today I’d put it on every read as well, and generate the list of endpoints and modules from one place so none is missed.

  6. 06

    Hand campaigns to a sender

    Email and SMS campaigns are planned, scheduled and counted, and the popup runs live. Next is a queue that hands them to a mail and SMS provider and writes delivery back to the list.
