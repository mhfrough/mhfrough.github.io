# Hire-me reel: how to make it (draft instructions, to become a project skill)

Scope: mhfrough.dev only. One kind of video: a **"Hire me" pitch**, **music only with on-screen text** (no voiceover),
**vertical 9:16 only** (owner, 2026-10-13: no square cut). The owner writes or approves the script; the skill builds,
renders and publishes from it. (The first script, `promo/reels/hire/script.md`, was drafted by Claude from the /hire
copy for the owner to edit.)

First reel built 2026-10-13: `promo/reels/hire/` (24 s, 120 BPM). Length target 20 to 25 s.

Method carried over from the Quorum reels (`D:\workspace-personal\quorum\promo\`): the reel is a web page timed by a
cue table, stepped frame by frame in headless Chromium with a fake clock, then muxed with PyAV.

## 1. Inputs (from the owner)

- `promo/reels/hire/script.md`: a shot list, one row per beat:
  `| # | on screen (exact text) | visual | min hold (s) |`. Plus the CTA and the length target (20 to 30 s).
- Music: by default an original bed generated by `promo/reels/tools/music.py` (numpy/scipy synth, no samples, no
  license), written to `promo/reels/hire/music.wav` (git-ignored, rebuilt by `reel.py music hire`). Its tempo is chosen
  so scene changes land on bar starts. A licensed track (Pixabay Content License or similar) can replace it: note the
  link and license in the script and keep the raw file git-ignored.

If anything in the script breaks the copy rules below, stop and ask; do not rewrite it silently.

## 2. Copy and content rules (same as the site)

- Facts only from `docs/content.md` (since 2020, 7+ years, 30+ products, 6 banking apps, 4 Angular apps ...).
- Never name employers or client banks. No photo of the owner: the ء mark on its tile stands in.
- Zero em or en dashes. No filler verbs. CTA label is exactly "Hire me"; the URL shown is `mhfrough.dev/hire`.
- Availability, if shown, is the `.status-pill` + `.blip.is-on` look.

## 4. The reel page (`hire/reel.html`)

**Format.** Stage 1080x1920. Every size is written in site pixels times `--u` (2.9px), so proportions match the
site. The page still accepts `?format=square` (1080x1080, `--u` 1.95px) if a square cut is ever wanted, but it is not
rendered by default.

**Safe zones.** Keep text out of the top 250px and bottom 380px (Reels/TikTok/Shorts UI) and 90px sides. Half-width
cards are too narrow for mono tags at this size: keep cards to icon + title, rows to icon + one line.

**Look: this site's system, not Quorum's.**
- Tokens copied from `src/styles/_tokens.scss` (`--bg #111`, `--surface`, `--ink`, `--muted`, `--line`, radii 16/12,
  pills 999px). Monochrome. Geist for type, Geist Mono for commands, numbers and small captions.
- Pieces to reuse: the ء tile + "mhfrough" pill, `.display` headline with a `.soft` second line, `.card` and bento
  cells, `.chip`, `.tag`, `.cmd` bar, `.status-pill` with the sonar blip, the `<mh-pattern>` Truchet field (port its
  canvas logic into the page, seeded, with a scripted "pointer" instead of the mouse).
- Show real things built with the site's components (a numbers band, offer cards, the process rail, a project bento
  with favicons from `public/images/<page>/`), never fake screenshots or photos of the owner.
- Restrained motion only: masked line reveals, rise, fade, small pops, typing in the `.cmd` bar, slow drifting glow.
  No custom cursors, bounces on everything, or decorative geometry.

**Timeline.**
- One `CUES` object holds every beat time in seconds. A small script turns cues into CSS variables (`--d` in,
  `--o` out) and `data-in="s2+.3"` attributes. Retiming is one edit.
- Music-led timing (no voice): note the track's BPM and the second of its first downbeat in the script; snap cues to
  beats (`beat = 60 / BPM`). Big changes land on bar starts.
- Reading time: each text block holds at least `0.9 s + 0.3 s per word`. The CTA holds still for the last 2.5 s or
  more, and the music's ending (or a fade) lands after it.
- JS beats (typing, pattern ripples, counters) run from a `BEATS` list via `setTimeout`.

**Render contract.**
- `body.hold` pauses every animation until fonts and assets load.
- `window.reelReady` (promise, sets `window.REEL = { duration, format }`) and `window.startReel()`.
- Seeded `Math.random` so every render is identical. Without `?render` the page plays itself for live preview.

## 5. Render (`tools/render.mjs`)

- Set the `.devcache` env vars from CLAUDE.md first. Playwright Chromium from the repo's `node_modules`, browsers in
  `.devcache/playwright`.
- Viewport 1080x1920, `deviceScaleFactor: 2` (master 2160x3840), 30 fps.
- `page.clock.install()` + `pauseAt`; per frame: `clock.runFor(1000/30)`, then pause and seek every
  `document.getAnimations()` to the frame time, then a JPEG q95 screenshot.
- `stills` mode: 1x PNGs at chosen seconds, for checking before a full render.
- The renderer serves the repo root on :5528 itself (a tool server, not a preview server; the site preview stays on
  :4300).

## 6. Mux (`tools/mux.py`) and outputs

- Music only: no `--vo`, so no ducking. Music trimmed by an offset so its ending lands after the CTA; 0.4 s fade in,
  1.5 s fade out; normalised to -14 LUFS with a -1 dBTP limiter.
- Master (for upload to LinkedIn, Instagram, etc.): H.264 High, CRF 16, preset slow, AAC 192k, `+faststart`, in
  `promo/reels/out/hire-9x16.mp4` (git-ignored).
- Web version (served by the site): downscaled to 1080x1920, CRF 21, `public/videos/hire-9x16.mp4`. Target under 6 MB.
- Poster: the frame at the script's poster time, WebP q80, 720x1280, `public/videos/hire-9x16.webp`.

## 7. On the site

- Placement: on /hire (exact spot decided with the owner).
- `<video controls playsinline preload="none" poster="...webp">`, not autoplaying with sound, in a 9:16 frame.
- Inside `@defer (on viewport)` with `<mh-skeleton>` as the placeholder, per CLAUDE.md.
- Accessibility: the video has no speech, so give a text alternative next to it: a short visible "What the video
  says" list of the on-screen lines (WCAG 1.2.1). No captions track needed.

## 8. Commands

```bash
python promo/reels/tools/reel.py music  hire                    # regenerate music.wav
python promo/reels/tools/reel.py stills hire 1.5,8.5,12.5,21.5    # PNG checks in .devcache/reels/hire/stills
python promo/reels/tools/reel.py all    hire                    # frames + master + web + poster (about 15 min)
python promo/reels/tools/reel.py mux    hire                    # new music or offset, reuse frames
```

## 9. Checklist before calling it done

- Stills at every cue: nothing in the safe-zone margins, nothing clipped, no overlapping text.
- Every line on screen matches the script and the copy rules (search for dashes and employer names).
- Mux summary shows about -14 LUFS and <= -1 dBTP; the music ending lands after the CTA.
- The web file plays in the dev server on :4300 with their posters; file sizes within target.
- Text alternative present; Lighthouse and axe pass on /hire.
